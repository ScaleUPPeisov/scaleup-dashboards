# Синтетические проверки изоляции APEX

Стенды работают только с временными фиктивными файлами и локальным HTTP-сервером. Они не запускают VYRON и не изменяют guard приложения.

25.11.2026 на macOS проверка `webkit_filters_probe.py` показала следующее:

- `sandbox-exec` запретил сетевое подключение родительского процесса, но без дополнительных правил WebKit обратился к локальному серверу.
- Предварительно скомпилированные `WKContentRuleList` вместе с `WKNavigationDelegate` заблокировали в отдельном WKWebView проверенные HTTP и WebSocket запросы: fetch, XHR, Beacon, WebSocket, CSS/import, изображение, iframe и redirect. Контрольные запуски без правил подтвердили, что каждый запрос способен дойти до сервера. Отдельный тест разрешал исходный redirect и блокировал его цель.
- Компиляция правил после входа в песочницу на этом стенде завершилась ошибкой WebKit с кодом 6; использование заранее скомпилированного списка позволило загрузить правила в тесте.

Результат относится только к этому стенду и не подтверждает изоляцию VYRON, WebKit/XPC в целом, HTTPS/WSS, WebRTC, service worker, пользовательских схем, внешних программ и файловых операций. Фильтр тестирует URL-правила и не заменяет системные ограничения. До проверки всей цепочки запуск experimental APEX остаётся заблокированным. Для повторного системного запуска используйте `python3 scripts/apex_isolation/webkit_filters_probe.py`; результат кроме `all_filter_blocked_fixture_requests` означает ошибку или недостаточность данных.

26.11.2026 отдельный `file_read_probe.py` проверял чтение фиктивных каталогов. Контрольный WKWebView прочитал оба изображения, но процесс со строгим запретом чтения завершился с кодом -6 до начала проверки. Результат `inconclusive_sandbox`: изоляция файлов не доказана, а старт приложения по этому стенду не разрешается.
